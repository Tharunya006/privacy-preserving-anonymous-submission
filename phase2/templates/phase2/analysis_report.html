{% call learn_more("What does the signature prove?") %}

Signed: the SHA-256 of the stored encrypted title, the encrypted report text and every stored evidence file, plus the report number, its received time, the signing time, the key ID and, for each evidence file, its number, stored name, type, size and time. Status changes are not signed, because they change during normal work.

Valid means none of that stored data has changed since the server accepted the report, and that it was signed with a key this server trusts. It does not identify the source (sources stay anonymous) and says nothing about whether the report is true. Anyone with full control of the server and its private key could still sign different data.

Any other result means the check did not succeed: treat the report's stored data as unverified.

{% call learn_more("What these bytes are, and what the digest does and does not mean") %}

Envelope = the complete stored package exactly as stored: "P5", version, protected timestamp, nonce, ciphertext, GCM tag and HMAC (for text, the base64url-decoded database value; for evidence, the stored file). Payload = the AES-GCM ciphertext alone. Envelope size = payload size + 71 bytes.

The SHA-256 is a digest of stored encrypted bytes, not of the original report or file. It is not proof of authenticity: anyone able to change the stored bytes can recompute it. Authenticity is checked with the server's HMAC key when a journalist opens the report.

Equality and linkability. Two equal digests mean identical stored bytes, so this digest can link copies of the same stored item (for example in a backup or export) to this report. Because every encryption uses a fresh random nonce, the same report or file submitted twice gives different envelopes and different digests, so digests do not reveal repeated content. Digests are shown to administrators only and are never written to logs, URLs or the audit log.

Entropy and the byte distribution use at most the first 2 MiB; the digest always covers all the bytes.
