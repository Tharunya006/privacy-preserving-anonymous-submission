Four different tools. Only the first one is analysed on this page.

MechanismSecret key?What it showsWho can make / check itUsed in this project
SHA-256 hash No A fixed-size fingerprint: any change to the input gives a completely different digest. It does not show who made it. Anyone Submission tokens are stored only as their SHA-256 digest; SHA-256 is also the building block of HMAC and of password hashing (PBKDF2-HMAC-SHA-256).

{% call learn_more("Why these tests, and what they cannot show") %}

Model and assumptions. An ideal hash behaves like a random function: the digest of every different input is an independent random 256-bit string, so changing any input bit flips every output bit with probability ½, independently. Four consequences are tested — balance (flip rate), each output bit (χ²), independence between output bits (variance test) and relation between the two digests (φ) — each at α = 0.001. With many output bits some deviation is always expected by chance, so each value is compared with its sampling error rather than with an exact target. Four tests mean about a 0.4 % chance of a false alarm per run.

Reading the result. "No evidence of deviation" means no test rejected. It is not proof of security, and p-values are not probabilities that SHA-256 is secure.

A weak function (for example one that just copies part of its input) fails these tests badly; the project's tests check that. SHA-256 passing them is necessary but nowhere near sufficient for security.

Limitations

  • Statistical tests can reveal obvious bias; passing them does not prove a hash is secure.
  • Sample sizes are small (thousands of hashes); real cryptanalysis studies far more and uses mathematical analysis.
  • The preimage and second-preimage examples attack SHA-256 truncated to 8–16 bits. They show how the cost of a generic brute-force search grows (2ᵗ), not that full SHA-256 cannot be broken by some other method.
  • The 256-bit estimate assumes brute force on classical computers; Grover's algorithm on a large quantum computer would need about 2¹²⁸ steps instead, which is still far out of reach.
  • Collision resistance (any two messages with the same digest, cost about 2¹²⁸) is a different property and is not tested here.
  • Messages come from a fixed-seed generator, so the page is reproducible; it uses no real report, token or key.
